Overview

Fit4steps will run on a single connected platform built with Flutter and Firebase. Administrators and staff or trainers manage day-to-day operations through secure web dashboards, while clients and their family members use a mobile app for Android and iOS. Zoho is used for lead management only; all operational data, sessions, health records, memberships, and payments, lives in Firebase.

Firebase provides authentication, database, storage, serverless business logic through Cloud Functions, and push notifications. This proposal sets out the roles, user flows, screen scope, technology, all charges, and the terms of engagement.

User flows

Client onboarding & login
Open app → enter mobile number → receive OTP → verify → land on dashboard (next session, membership, progress).
Book, cancel or reschedule a session
Dashboard → Sessions → choose slot and trainer → confirm → reminder scheduled. Cancel or reschedule within the notice window; affected parties notified.
Trainer session & health entry (web)
Trainer logs in → today's schedule → mark attendance → enter assessment and progress → saved to platform → client app updates and client is notified.
Family member invitation & access
Client → Family → invite (name, relation, mobile) and set permissions → family member logs in by OTP → sees permitted data → receives notifications.
Payment & renewal
Client or family → Membership → pay or renew via gateway → invoice generated and downloadable → renewal reminder scheduled.
Notifications (automated)
Cloud Functions trigger session reminders, trainer-arrival alerts (from trainer or admin action), payment reminders, and health tips, delivered by push.
Admin operations (web)
Admin logs in → dashboard → manage clients, trainers, sessions, memberships, payments → configure notifications and content → review leads synced from Zoho.

Payments via Razorpay

Membership payments and renewals in the client app are processed through Razorpay, integrated into the in-app checkout. Razorpay supports UPI, debit and credit cards, net banking, and wallets.

How it works

Client or family taps pay or renew → Razorpay checkout (UPI, card, net banking, wallet) → payment authorised → Razorpay confirms to Cloud Functions by webhook → invoice generated and membership updated → funds settle to the Fit4steps bank account in about T+2 business days.

Commission (per successful transaction)

Payment methodRazorpay fee
UPI, debit, credit, net banking, wallets (domestic)2% + 18% GST (≈ 2.36%)
EMI, Amex / Diners, Pay Later (premium)≈ 3% + GST
International cards3% + GST
Setup fee / AMCNone

GST applies to the Razorpay fee only, not the full transaction value. UPI carries zero MDR, so a higher UPI share lowers the blended rate. Domestic payments settle in about T+2.

Worked example — ₹1,000 payment (standard 2%)

Razorpay fee (2%)₹20.00
GST on fee (18%)₹3.60
Total deducted₹23.60
Net settled to Fit4steps₹976.40
Costing. Razorpay charges only on successful transactions, deducted automatically, with no fixed monthly or setup cost. This is a running cost on Fit4steps revenue and is borne by the client. Razorpay integration into the app is included in the development scope; the transaction fees themselves are not a Brilworks charge.

Alternative: client app only (Zoho web for admin & staff)

A lighter, lower-cost engagement. Fit4steps takes only the client mobile app; administrators, staff, and trainers continue to work in Zoho's own web interface, so no custom admin or trainer dashboards are built. The app is backed by a light Firebase layer (Cloud Functions) that securely brokers calls to the Zoho CRM and app APIs. Zoho remains the operational record store, not lead-only.

The light backend keeps Zoho credentials server-side, never on the device, handles OTP, powers push notifications, and confirms payments by webhook. It caches and batches Zoho calls to stay within Zoho's included API limits.

Scope limits

This option builds the client app plus the light Firebase broker only. It does not include custom admin or trainer web apps (staff use Zoho's own web) or family-member access and permissions, which remain full-platform features. What the app can show depends on the data Zoho holds and exposes through its API. OTP uses Firebase Phone Auth or an SMS route (see OTP costs in Section 07).

Running costs for this option: OTP / phone verification, Razorpay transaction fees, app-store fees, light Firebase usage (Cloud Functions for the API broker and notifications, typically within free quotas), and Zoho API usage.

Zoho API cost

Zoho CRM meters API access with a daily credit system that is included with the client's existing edition: about 50,000 base credits per day plus a per-user allowance (roughly 250, 500, or 1,000 credits per user on Standard, Professional, and Enterprise). Most calls cost one credit. For this user base, and with the broker caching and batching calls, usage normally stays within the included credits at no extra cost. If sync volume exceeds them, additional Zoho API credits are inexpensive (about ₹13 per 1,000 credits for the first slab) and are borne by the client.

How this differs from the full platform. The full platform (Section 07) uses Firebase as the system of record and adds custom admin and trainer web apps and family access. This option keeps Zoho as the record store, uses Zoho's own web for staff, and builds the client app plus a light Firebase broker.
